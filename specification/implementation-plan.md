## 1. マップ・キャラクター・通常攻撃の基盤

状態：実装済み。最終修正後の実行テストはWindowsのアプリケーション制御により未完了。

- マッチングのカウントダウンからゲームシーンへ遷移する。
- マップ、4キャラ、施設との衝突、50Uグリッドの経路探索、廃墟と共有視界を実装する。
- 右クリック移動、近接・遠隔の通常攻撃、射程外への追跡、停止、攻撃キャンセルを実装する。
- HP・マナ・基礎能力、死亡・復活・8秒リコール、基本的な撃破報酬を反映する。
- ミニマップ、追従／自由カメラ、ズーム、対象情報、復活待ちを表示する。
- キャラ／マップ定義、入力、描画を分離し、サーバー判定・位置補間・再接続時の状態復元を整える。
- 既存の通信テスト・ブラウザーテストをゲームシーンまで拡張する。

完了条件：2人が同じ戦場で移動・交戦・死亡・復活できる。障害物を貫通せず、視界外の敵の現在位置を配信しない。入力の重複や切断で他人のキャラを動かせない。

この段階では施設は配置と衝突のみ。工作員・施設攻撃・Q/W/E・パッシブ・サモナースペル・ショップは後続ステップで実装する。通常攻撃のキャラ差は基礎能力と近接／遠隔に限る。

### 実装と検証の記録（2026-10-01）

- UIの `GameScene.tsx` / `gameRenderer.ts` / `world.ts` と、サーバーの `definitions.go` / `navigation.go` / `game.go` / `game_input.go` / `combat.go` を追加。既存ロビーから `playing` へ接続した。
- 最終修正前のGoテストとブラウザーテストは成功。独立した2プレイヤーでマッチング、移動、通常攻撃、死亡、リロードによる再接続、復活、リコール、退出を確認した。1024×576で横方向のはみ出しがないことと、ブラウザーの実行時エラーがないことを確認した。
- その後、施設の角をまたぐ表示補間、キャラ画像のクリック判定、被弾とリコール完了が重なった場合の処理、飛び道具の発射直後の進行時刻を補強した。再接続・リコール完了時の被弾・発射者死亡後の飛び道具についてGoテストを追加した。
- 最終版の `npm run build`、`npm run lint`、`go vet ./...` は成功。
- 最終版の `go test ./... -count=1` と `go run .` は、生成された実行ファイルに対する `An Application Control policy has blocked this file` で起動できなかった。テストのアサーション失敗ではない。制御設定は変更していない。最終版のGoテストとブラウザーテストの再実行は未完了で、現時点ではGoサーバーは停止している。
